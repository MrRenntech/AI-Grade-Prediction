DEVELOPMENT STEPS - STUDENT PERFORMANCE AI
==========================================

This document outlines the step-by-step process used to build this project.

STEP 1: PROJECT SCAFFOLDING & DATA SETUP
----------------------------------------
1.  Created the project directory structure:
    - `data/` for datasets.
    - `src/` for source code (preprocessing, training, evaluation).
    - `models/` for saved models.
    - `app/` for the web application.
    - `notebooks/` for experimental notebooks.
2.  Added the dataset `student-mat.csv` to the `data/` folder.
3.  Created `requirements.txt` with necessary libraries: pandas, numpy, scikit-learn, matplotlib, seaborn, flask, joblib.

STEP 2: DATA PREPROCESSING
--------------------------
1.  Created `src/data_preprocessing.py`.
2.  Implemented `load_and_preprocess()` function to:
    -   Load data from CSV.
    -   Combine G1 and G2 grades into a new feature `G1_G2_AVG`.
    -   Define the target variable `Risk` (1 if G3 < 10, else 0).
    -   Drop the original `G3` column to prevent data leakage.
    -   Encode categorical variables using One-Hot Encoding.
    -   Scale numerical features using StandardScaler.
    -   Handle class imbalance using SMOTE (Synthetic Minority Over-sampling Technique).

STEP 3: MODEL TRAINING & EVALUATION
-----------------------------------
1.  **Data Splitting**:
    -   Split the dataset into Training (80%) and Testing (20%) sets.
    -   Used `stratify=y` to ensure the proportion of "At-Risk" vs "Safe" students remained consistent across both sets, which is crucial for imbalanced datasets.

2.  **Model Selection & Training**:
    -   We trained and compared two distinct algorithms:
        -   **Logistic Regression**: A linear model used as a baseline.
        -   **Random Forest Classifier**: An ensemble learning method (200 trees) that effectively handles non-linear relationships and interactions between student features.

3.  **Performance Results**:
    -   **Logistic Regression**: Achieved approximately **84.8% accuracy**.
    -   **Random Forest**: Outperformed the baseline with approximately **91.1% accuracy**.
    -   *Why Random Forest?* It showed superior performance due to its ability to model complex decision boundaries without overfitting, making it the ideal choice for this risk prediction task.

4.  **Model Serialization**:
    -   The best performing model (Random Forest) was saved to disk as `models/student_risk_model.pkl` using the `joblib` library, allowing it to be loaded later by the web application for real-time predictions.

STEP 4: MODEL EVALUATION
------------------------
1.  Created `src/evaluate_model.py`.
2.  Loaded the test data and the saved model.
3.  Generated performance metrics:
    -   **Confusion Matrix**: To visualize true vs. false predictions.
    -   **Classification Report**: Precision, Recall, and F1-Score for each class.
    -   **ROC-AUC Score**: To measure the model's ability to distinguish between classes.
4.  Plotted and saved the **ROC Curve** to `models/roc_curve.png`.

STEP 5: ADVANCED ANALYTICS (Risk Scoring & Explainability)
----------------------------------------------------------
1.  **Risk Scoring (`src/risk_scoring.py`)**:
    -   Implemented a probability-based scoring system.
    -   Instead of simple binary classification, we use `predict_proba()` to get the confidence of the model.
    -   Defined tiers:
        -   **High Risk**: Probability >= 0.75 (Requires immediate intervention).
        -   **Moderate Risk**: Probability between 0.50 and 0.75 (Monitor performance).
        -   **Low Risk**: Probability < 0.50 (No immediate action).
2.  **Feature Importance (`src/feature_importance.py`)**:
    -   Extracted feature importance scores from the trained Random Forest model.
    -   Created a visualization (`models/feature_importance.png`) to identify top factors contributing to student failure (e.g., past failures, grades, absences).

STEP 6: WEB APPLICATION PREDICTION SYSTEM
-----------------------------------------
1.  **Backend (`app/app.py`)**:
    -   Initialized Flask application.
    -   Loaded trained model (`student_risk_model.pkl`) and encoders (`encoders.pkl`).
    -   *Crucial Step*: Ensured consistent data preprocessing by saving the `LabelEncoder` objects from training and applying them strictly to user input during inference.
2.  **Frontend (`app/templates/index.html`)**:
    -   Created a "Rich Aesthetics" dark-mode interface with a clear, responsive form.
    -   Implemented AJAX for seamless, page-refresh-free predictions.
3.  **Integration**:
    -   Connected the frontend input to the backend prediction logic.
    -   Displayed dynamic risk alerts ("High Risk", "Safe") with confidence levels and recommended actions.

STEP 7: MINIMAL FLASK APP (Re-implementation)
---------------------------------------------
1.  **Refactoring for Simplicity**:
    -   Replaced the complex frontend/backend with a minimal, robust version as per specific requirements.
    -   **Backend (`app/app.py`)**: configured to accept simplified JSON payloads (e.g., handling missing columns via zero-filling) and return raw probability data alongside the risk prediction.
    -   **Frontend**: Simplified to a placeholder status page, shifting focus entirely to the API capabilities.
2.  **API Verification**:
    -   Verified the `/predict` endpoint using `requests` with simplified data payloads (e.g., using `avg_grade` instead of specific semesters).
    -   Confirmed robust error handling and correct probability calculations.

STEP 8: FINAL FRONTEND IMPLEMENTATION
-------------------------------------
1.  **Form-Based Interface**:
    -   Replaced the placeholder index.html with a full production-ready form.
    -   Supported inputs: Age, Study Time, Absences, Average Grade.
    -   Implemented dynamic risk visualization (Low/Medium/High) with color coding.
    -   Displayed extensive details: Risk Score, Confidence, Probability Breakdown, and Recommended Actions.

STEP 9: PACKAGING & DEPLOYMENT
------------------------------
1.  **Executable Generation**:
    -   Used PyInstaller to package the Flask application into a standalone `.exe`.
    -   Command: `python -m PyInstaller --name student_risk_predictor --add-data "app/templates;templates" --add-data "models;models" --add-data "data;data" --paths . --onefile app/app.py`
    -   Ensured all dependencies (sklearn, pandas, templates, models) were bundled correctly.
2.  **Documentation Update**:
    -   Updated `PROJECT_TREE.txt` with detailed file descriptions.
    -   Updated `HOW_TO_RUN.txt` with instructions for the executable.

STEP 10: SGPA PREDICTION MODEL (Intelligence Layer Step B)
--------------------------------------------------------
1.  **Data Strategy**:
    -   Since the UCI dataset lacks SGPA, we simulated SGPA bands based on G3 (Final Grade).
    -   Mapped grades <10 (Band 0), 10-11 (Band 1), 12-13 (Band 2), 14-15 (Band 3), >=16 (Band 4).
2.  **Model Training**:
    -   Trained a separate Random Forest Classifier (`src/train_sgpa_model.py`) to predict these bands.
    -   Used only inputs available *before* finals (Age, Absences, StudyTime, Internal Avg).
    -   Achieved solid accuracy (~67% for 5-class banding), proving realistic predictive capability.

STEP 11: CGPA PROJECTION LOGIC (Intelligence Layer Step C)
----------------------------------------------------------
1.  **Deterministic Formula**:
    -   Implemented the standard academic formula: `((Current CGPA * Completed Semesters) + Projected SGPA) / (Completed Semesters + 1)`.
    -   This ensures the projection is mathematically sound and defensible to faculty.
2.  **Band Mapping**:
    -   Created a conservative mapping from SGPA Band to numerical value (e.g., Band 3 (8-9) -> 8.5) to allow for safe projection.

STEP 12: INTEGRATED DECISION SUPPORT SYSTEM (Intelligence Layer Step D)
-----------------------------------------------------------------------
1.  **Backend Integration**:
    -   Updated `app/app.py` to run both models (Risk + SGPA) in parallel.
    -   Constructed a unified JSON response containing Risk Level, Risk Score, Predicted SGPA Range, and Projected CGPA.
2.  **Frontend Upgrade**:
    -   Updated `index.html` to accept academic history inputs (Current CGPA, Semesters).
    -   Redesigned the results dashboard to present a professional, "Academic Report" style view, focusing on clear metrics and recommendations rather than raw probabilities.
